# Architecture

FaraX is a single [Django] project at the root of the repository (see
[ADR 0001](../adr/0001-single-repository.md)), with the standard layout generated by
`django-admin`: the project package `farax/` and a single app `main/`. `farax` also
provides `farax.__version__`, derived from git tags by `setuptools-scm`, so it only
exists when FaraX is installed.

## Settings

`farax/settings/` is split in two. The base settings (`farax.settings`) need no
configuration and are used for local development and the tests. The production
settings (`farax.settings.production`) extend them, turn debug mode off, and read the
secret key, allowed hosts, PostgreSQL connection and SMTP email server from environment
variables (see [Production settings](index.md#production-settings)). They also add
[WhiteNoise] so the app serves its own static files.

## Database

PostgreSQL is used in production and CI; SQLite (in the git-ignored `db/` directory) is
tolerated for local development only (see
[ADR 0002](../adr/0002-postgresql-with-sqlite-for-local-development.md)). The base
settings use PostgreSQL, through psycopg, when `POSTGRES_DB` is set, and SQLite
otherwise.

## User model

`main.User` subclasses Django's `AbstractUser` without adding fields. It is the
`AUTH_USER_MODEL` from the first migration, so it can be extended later without a
difficult migration.

The "Admin" group is created by a data migration with permissions to view, add, change
and delete user accounts. The migration marks any existing members as staff, which is
required to use the admin site. Users subsequently assigned to the group through Django
Admin are also made staff by `SafeUserAdmin`. `SafeUserAdmin` stops non-superusers making
anyone a superuser or changing or deleting superuser accounts. Accounts that are not
staff cannot use the admin site.

## Schema registry (proposed)

The schema registry described in the [proposed design](schema-registry.md) and
[ADR 0004](../adr/0004-immutable-registered-schemas.md) is not implemented yet.

## File Store

Raw Files are kept unchanged in the File Store, not in the database (see
[ADR 0003](../adr/0003-raw-files-in-file-store.md)). It is the default storage in
`STORAGES`: a `FileSystemStorage` in the git-ignored `media/` directory, or the
directory set by `DJANGO_MEDIA_ROOT` (a named volume under Docker Compose).
